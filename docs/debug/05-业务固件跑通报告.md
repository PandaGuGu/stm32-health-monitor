## 一、结论

**屏幕不亮的根因找到了，不是屏坏，是固件卡死。**

`USER/main.c` 的业务固件里有一处**无超时死循环**：

```c
// HARDWARE/IIC/myiic.c:51   —— max30102_init() 内部
while(READ_SDA)          // 等 MAX30102 的 I2C ACK，模块不在线就永远等不到
```

调用链：`main() → max30102_init() → myiic.c:51`。
MAX30102 此刻零电气连接 → 永远没有 ACK → **固件停在这里，`MPU6050_Init()` / `ds18b20_init()` / 主循环全部不执行**。

即使绕过这一处，后面还有两处：

```c
// USER/main.c:104 / :141
while(MAX30102_INT==1);  // INT 脚悬空 → 死等
// HARDWARE/DS18B20/ds18b20.c:68-69
while(GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_8));   // DS18B20 不在线 → 死等
```

所以之前看到的现象全都解释得通：**板子有电、ST-Link 能连、OLED 却不显示任何内容**——固件在 `OLED_Init()` 之后、`OLED_Update()` 之前就停住了（准确说，第一屏静态标签能画出来，之后再也不刷新）。

## 三、实测证据（SWD 直读，非推断）

编译结果：`FLASH 8112 B / 12.4%`，`RAM 6800 B / 33.2%`。烧录 `Verified OK`。

| 子系统 | 引脚 | 实测值 | 判定 |
|---|---|---|---|
| **MCU 运行** | — | `PC = 0x080006e2`，`app_cycle = 15`（约 6 s 内 15 轮） | ✅ 主循环在跑 |
| **OLED** | PA5 / PA6 | 显存 `OLED_DisplayBuf[8][128]` **361/1024 字节非零，8 行全有内容** | ✅ 固件确实在写屏 |
| **DS18B20** | PA8 | `app_ds_ok = 1`，应答拉低 `10 µs`，`Temp = 27`（℃） | ✅ 读到真实温度 |
| **MPU6050** | PB10 / PB11 | `AX=-775 AY=1687 AZ=-662`，`GX=13 GY=-22 GZ=-34`，`Last_AX=-789 Last_AY=1683` | ✅ 实时数据 |
| **蜂鸣器** | PA12 | `GPIOA_CRH` 中 PA12 = `0b0011`（推挽输出 50 MHz），`GPIOA_ODR` bit12 = 1（空闲高=关） | ✅ 已初始化 |

**几个数值的交叉验证：**

- **DS18B20 = 27 ℃** —— 不是上电默认的 85 ℃，说明"复位→跳过 ROM→启动转换→等 750 ms→读暂存器"整条时序真正跑通了，读到的是真实室温。
- **加速度合成模长** = √(775² + 1687² + 662²) ≈ **1971** ≈ 0.96 g（模块量程 ±16 g 时 1 g ≈ 2048 LSB）。**模长接近 1 g，证明是真实的重力测量，不是噪声或残留值。**
- **`app_cycle = 15`** 与主循环单轮耗时吻合（DS18B20 转换 750 ms + OLED 整屏 1 KB 位翻转刷新），节奏正常。

## 四、通电后屏幕应显示

```
温度：27℃
心率：--
血氧：--
是否跌倒：否
```

开机瞬间蜂鸣器**短鸣两声**。

- 心率 / 血氧显示 `--` 是预期行为（MAX30102 已关闭）
- 拿起板子晃动，`是否跌倒` 行会变 `是`，蜂鸣器长鸣；放平后恢复 `否`
- 晃动时 SWD 读到的 `AX/AY/AZ` 数值会跟着变

**如果屏幕仍然全黑**，那就与固件无关了（显存已证明有内容），只剩两种可能：
1. OLED 模块需要重新上电——**把板子 VCC 拔掉等 5 秒再插**（SSD1306 有卡死的情况）；
2. 模块本身损坏。

## 五、MAX30102 的状态

**本版已按你的要求排除。** 它的电气状态没有变化，仍是零痕迹：

```
PB7 (SCL) RC 电容计数 = 3   ┐
PB8 (SDA) RC 电容计数 = 4   ├ 与裸脚基线（PA0=2、PA11=3）同级
PB9 (INT) RC 电容计数 = 3   ┘
全板外部上拉只有 5 根针：PA5/PA6(OLED)、PA8(DS18B20)、PB10/PB11(MPU6050)
256 个 I2C 地址扫描 ACK = 0
```

即：**这四根针上连一根导线该有的那点电容都没有**。要接回它，请参考 `MAX30102专项诊断_v1.5.md`（隔离测试：SCL→PB10、SDA→PB11）。

接回后重新编译**完整业务固件**（含 MAX30102）：

```bash
SHELL=/usr/bin/bash $MAKE -j4        # 缺省即 IIC 目标
```

## 六、复现命令

```bash
export PATH="$HOME/tools/xpack-arm-none-eabi-gcc-14.2.1-1.1/bin:$PATH"
MAKE=/c/mingw/mingw64/bin/mingw32-make.exe
cd firmware/MAX30102/gcc

python app/make_app.py                       # （改过 USER/main.c 才需要）重新派生 app_main.c
SHELL=/usr/bin/bash $MAKE -j4 APP=1          # 编译业务固件（MAX30102 关闭版）
```

烧录必须用 **`adapter speed 20`**（杜邦线较长时高频握手会失败）：

```bash
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
        -c "adapter speed 20" -c "init" -c "reset halt" \
        -c "program build/APP.elf verify" -c "reset run" -c "exit"
```

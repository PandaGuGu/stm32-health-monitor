## 二、关键改进：现在可以「边插边看」

固件已升级，**每 3 秒自动重跑一轮完整扫描**，所以：

> 你改一根线，OLED 上 3 秒内就会变。**不需要我再重新烧录。**

### OLED 现在的显示

```
DIAGLIVE 016          ← 循环计数，在跳 = 固件活着
M1-- M2-- ack0        ← M1=PB7/PB8 总线, M2=PB10/PB11 总线, ack=应答个数
MPU. 68 DS. 110       ← MPU/DS 状态 + 应答us
P7=3  P8=3  P9=3  A8=0    ← 关键引脚 RC 计数
A5=0  A6=0  B10=0 B11=0   ← 已知正常引脚（对照组）
```

**读法（重要）：**

| 引脚 RC 读数 | 含义 |
|---|---|
| **0** | 该线上挂着**有供电的器件**（器件的上拉把线瞬间拉高）—— 这是「接好了」 |
| **2~3** | **裸脚**（只有几 pF 的引脚电容）—— 没接线 |
| **>10** | 只接了线、但线的那头没有上拉（悬空的长线） |

看最后两行的**对照**：`A5/A6/B10/B11` 全是 **0**（那四个元件确实接好了），而 `P7/P8/P9` 是 **3**——和裸脚一模一样。

## 三、实测原始数据（16:52）

### 3.1 外部上拉普查（哪根针上真的挂了器件）

```
PA 外部上拉掩码 = 0x1160  →  bit5(PA5) bit6(PA6) bit8(PA8) bit12(PA12)
PB 外部上拉掩码 = 0x0C00  →  bit10(PB10) bit11(PB11)
被拉低掩码      = 0x0000 / 0x0000   （没有任何针被拉死）
```

- PA5/PA6 → OLED ✅
- PA8 → DS18B20 ✅
- PA12 → 板载 USB D+ 的 1.5 kΩ（单片机自带，与元件无关）
- PB10/PB11 → MPU6050 ✅
- **PB7 / PB8 → 无上拉** ❌

### 3.2 全引脚 RC 电容计数（裸脚基线 = 2）

```
PA[0..15] = 2  2  2  2  2  0  0  2  0  2  2  3  0  0  0  0
                         ↑  ↑     ↑              ↑
                      PA5 PA6   PA8           PA12(USB)
                        └─ 0 = 挂着有供电的器件

PB[0..15] = 2  2  2  3392  0  2  2  3  3  3  0  0  2  2  2  2
                   ↑    ↑           ↑  ↑  ↑  ↑  ↑
                 PB3  PB4        PB7 PB8 PB9 PB10 PB11
              (JTDO) (NJTRST)      └── 3 ≈ 裸脚 ──┘  └ 0 = MPU ✅
```

**PB3=3392 / PB4=0 是假信号**（JTDO / NJTRST 被 JTAG 接管，写寄存器不生效），忽略。

**PA11=3、PA12=0**：板载 USB 走线 + D+ 的 1.5 kΩ 上拉，属于单片机自身。

### 3.3 器件通信测试

```
MAX30102 (PB7/PB8)      found=0   PART_ID=0x00   全地址 ACK 数 = 0
M2 总线 (PB10/PB11)     ACK 数=1  唯一地址 0x68（只有 MPU6050）
MPU6050 (PB10/PB11)     found=1   WHO_AM_I=0x68  ✅
DS18B20 (PA8)           found=1   应答 110 us    ✅
```

**注意 M2 这一项**：在 PB10/PB11 这条**已被证明可用**的总线上，只扫到 MPU6050（0x68），**没有 0x57**。

| 信号 | 工程实际定义 | 出处 |
|---|---|---|
| MAX30102 SCL | **PB7** | `myiic.h:23` `#define IIC_SCL PBout(7)` |

## 五、诊断

PB7 / PB8 / PB9 三根针的电气状态，和**裸引脚**完全一致：

1. 无外部上拉（对比：A5/A6/A8/B10/B11 全都有）
2. RC 电容计数 3（对比：挂了器件的脚全读 0）
3. 全 256 个 I2C 地址，零 ACK

**三重独立证据指向同一件事：这三根针上没有接任何东西。**

这在物理上有两种可能，**用软件无法区分**：

| 可能 | 说明 |
|---|---|
| **A. 线根本没落在 MCU 的针上** | 面包板那一列没接通 / 杜邦线插在旁边的孔 / 线在面包板上但 MCU 排针没接触到 |
| **B. 线接对了，但 MAX30102 模块本身坏了 / 没供电** | 模块 VCC 没接、GND 没共、或模块已损坏 |

> 如果是「线接对了但模块没供电」，导线本身的分布电容（20 cm 杜邦线约 20~40 pF）也让 RC 计数明显 >3。现在读 3，更偏向 **A**。

## 六、决定性隔离测试（只改 2 根线，3 秒出结果）

**把 MAX30102 的 SCL / SDA 临时挪到 PB10 / PB11**（就是 MPU6050 已经验证可用的那条总线，可以并联，地址 0x57 和 0x68 不冲突）：

| MAX30102 | 改接到 |
|---|---|
| SCL | **PB10** |
| SDA | **PB11** |
| VCC / GND | 保持 |

**然后看 OLED 第 2 行：**

- 出现 **`M2OK`** → **模块是好的**，问题 100% 在 PB7/PB8 那两根线／排针上
- 仍然是 **`M2--`** → **模块本身有问题**（没供电 / 已损坏）

因为固件现在每 3 秒自动复扫，**你挪完线盯着屏看 3 秒就行**，不用叫我。

## 七、需要你确认的

1. **MAX30102 模块上有指示灯吗？** GY-MAX30102 板载一颗红色电源 LED —— **亮 = 供电通**，不亮 = VCC/GND 没接好。
2. **万用表量一根线**：MAX30102 的 SCL 杜邦线两端（面包板端 ↔ MCU PB7 排针）**通断档必须蜂鸣**。不看外观，只看响不响。
3. **量模块 VCC 对 GND** → 插着时应为 **3.3 V**。

第 1 条最快 —— 看一眼那颗红灯就知道了。

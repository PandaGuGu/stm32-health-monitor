## 二、故障速查表

| 现象 | 根因 | 修复 |
|---|---|---|
| 烧录/校验成功，但 OLED 全黑、所有传感器读数恒为 0 | `ds18b20.c:68` 处 `while(READ_DQ)` 无超时死等，DS18B20 未应答即永久阻塞在 `ds18b20_init()` | ① DS18B20 的 DQ 补 4.7 kΩ 上拉；② 用带超时的 DS18B20 实现（见 `gcc/app/app_main.c`） |
| OpenOCD 报 `init mode failed`，100 kHz 以上连不上 | 杜邦线过长/无屏蔽，高频握手失败（信号完整性问题，非软件） | **`-c "adapter speed 20"`**（20 kHz 是实测唯一稳定档位） |
| ST-Link 报 `LIBUSB_ERROR_TIMEOUT` | 设备句柄卡死 | `Disable-PnpDevice` + `Enable-PnpDevice` 软件重枚举（无需拔插） |
| RC 探针读到 `PB3 = 3392` 异常大 | PB3 = JTDO，复位后被 JTAG 控制器接管，写 `CRH` 不生效 → 读数是 JTAG 时序伪影 | 忽略 PB3/PB4；任何 DIY 引脚复用都不要用这两脚 |
| `PA12` 检出"外部上拉"，误判蜂鸣器已接通 | PA12 兼作 USB_DP，板载 1.5 kΩ 上拉是**单片机自带**，与蜂鸣器无关 | 不能据此判定；以"开机短鸣两声"为准 |
| 诊断固件运行中 OLED 突然全黑（屏亮但无内容） | `periodic_scan()` 的 `pin_survey_port(GPIOA, ..., 0xE600, ...)` 不跳过 PA5/PA6，把 OLED 两根线重配成输入；而 `oled_show()` 只改 ODR 不改 `CRL` → 此后永久空写 | 每帧前调用 `oled_pins_fix()` 把 PA5/PA6 恢复为开漏输出（`GPIOA_CRL = 0x87788888`） |
| `adapter speed` 用 `hla_swd` 无效果 | OpenOCD 0.12 已删除 `hla_swd`，静默忽略该参数 | 用 0.11 或放弃 `hla_swd`，直接调 `adapter speed` |
| **轻触板子/抖动线材就报跌倒**，而真跌落反而不报 | 跌倒判定一圈只跑一次（1.9 s 一次，0.52 Hz）：真冲击只有几十 ms，整段落在两次判定之间被漏掉；而判据又是"上一圈 vs 这一圈"的单轴差值，2 s 内翻 15° 就能变化 500 LSB | ✅ **2026-10-16 已修（见 `07`）**：判定挂进两段纯等待提到 **87.7 Hz**，判据改为**合矢量 \|a\| 去重力偏差**（倾斜免疫），阈值定标为 3072 LSB（≈2.5g） |
| 传感器线被碰掉后，**跌倒报警永久点亮**、`app_fall_hits` 疯涨 | MPU 掉电后三轴全返回 `0x00` → `\|a\| = 0` → `dev = \|0-2048\| = 2048` **恰好等于旧阈值** → 每拍都判命中 | ✅ **已修**：全零突发样本直接丢弃（计入 `app_mpu_zero`），不参与判定 |
| **手指拿开后屏幕仍显示上一次的心率/血氧**，且数字看着正常 | ① 显示层无条件画 `dis_hr` / `dis_spo2`，没有新值就**沿用旧值**；② `algorithm.c` 对心率**无生理范围约束**，无手指时从暗电平（直流 490 LSB）里凑出"峰"，报 `ch_hr_valid=1 / 300 bpm`；血氧查表照样返回 99 | ✅ **2026-10-16 已修（见 `08`）**：算法层加 **30–220 bpm** 门控；信号层加 5 项质量门控（直流/交流/灌注指数/实时接触）；连续 2 窗失败清空滑动窗。⚠️ **注意 `09` 又改了显示策略**：门控失败不再清屏，而是**有意保持**最后一次有效读数（用户明确要求） |
| 屏幕数字由 3 位变 2 位时**残留一位残影**（`119` 之后显示 `89` 会看成 `889`）；"是/否"切换叠字 | `OLED_ShowChar` / `OLED_ShowChinese` 都是**按位或**写入显存，不清区域就会叠字 | ✅ **2026-10-16 已修（见 `09`）**：画数字前先 `OLED_ClearArea(47,16,24,16)` / `(47,32,24,16)`，"是/否"前 `OLED_ClearArea(80,48,16,16)` |
| **Proteus 仿真里蜂鸣器一声不响** | 元件被勾了 **`Exclude from Simulation`**——模型被剥离（`Element` 栏为空、`Show All` 后 `Other Properties` 仍空），IO 怎么拉都没用；另外 `Operating Voltage` 默认 12 V，3.3 V 电源轨抬不动 | 取消勾选；若模型已丢则删掉重放 `BUZZER`；`Operating Voltage` 改 **3.3**；检查 Windows 音量合成器里 Proteus 是否被静音（见 `10`） |
| 仿真中 DS18B20 读数恒为 `0xFFFF`（换算成 4095，屏显像 `95`） | 工程加载的是 **`DS1822.MDF`**：presence 正常但命令写不进器件，数据位全读到高电平。实测 48 组时序（开漏/推挽 × 6 组时隙 × 2 种输入模式 × 2 种命令重发）全部失败 | 换 Pro 自带 `DS18B20`/`DS1621` 模型，或改用 **RV2 电位器 → PA0 的 ADC**（见 `10`） |
| 仿真心率恒定（如 68）、改 CLOCK 频率也不跟着变 | Proteus MCU 模型 `CLOCK_SCALE=8`（≈64 MHz），而固件按 **72 MHz** 标定 → 所有延时偏 12.5%，1 Hz 被测成 888 ms → `60000/888 ≈ 68`；加上 OLED 刷屏阻塞 200~400 ms，轮询采样还会漏边沿 | `Clock Scale` 改 **9 Times**；仿真演示用心率节律（见 `10`） |
| Keil 授权不可用 / 无法编译 | — | 改用 arm-none-eabi-gcc 独立构建（见 [`gcc/README.md`](../../firmware/MAX30102/gcc/README.md)） |

### 已知的代码/文档不一致（调试中发现）

| 项 | 文档/宏 | 实际代码 | 影响 |
|---|---|---|---|
| DS18B20 上拉 | 文档要求 4.7 kΩ 外部上拉 | `ds18b20.c:45` 仅用内部 IPU（约 40 kΩ）兜底 | 长线/劣质模块下不足以拉高，建议补外部电阻 |

## 三、复现命令速查

```bash
export PATH="$HOME/tools/xpack-arm-none-eabi-gcc-14.2.1-1.1/bin:$PATH"
cd firmware/MAX30102/gcc

# 编译（变体见 gcc/README.md）：缺省 IIC / APP=1 / LIVE=1 / DIAG=1
SHELL=/usr/bin/bash /c/mingw/mingw64/bin/mingw32-make.exe -j4 APP=1

# 烧录（adapter speed 20 是关键）
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
        -c "adapter speed 20" -c "init" -c "reset halt" \
        -c "program build/APP.elf verify" -c "reset run" -c "exit"

# 带电读回（自动解码 OLED 屏显 + PPG 质量门控 + 逐窗 trace）
python tools/ppg_read.py
```

## 五、Proteus 仿真

仿真**不是**实机，两者用的固件是分开的：

| | 固件 | 数据来源 |
|---|---|---|
| 实机 | `firmware/MAX30102/USER/main.c` | 全部真实传感器 |
| 仿真 | `firmware/MAX30102_sim/USER/main.c` | 温度=RV2 电位器（PA0 ADC），心率=内置节律，血氧=占位 97，跌倒=SW3(PB1) |

仿真工程 `sim/proteus/SIT_sim.pdsprj` 加载 `sim/proteus/IIC.hex`；改完仿真固件后需
重新编译并把 `firmware/MAX30102_sim/OBJ/IIC.hex` 复制到该路径。详细说明、引脚表与
"换回真传感器"的做法见 [`10-仿真固件说明.md`](10-仿真固件说明.md)。

# 显示层保持与异常高亮 v2.7

**日期**：2026-10-16
**固件**：`gcc/app/app_main.c`（由 `gcc/app/make_app.py` 生成）→ `make APP=1`
**构建尺寸**：`text 13860 / data 24 / bss 14072`（RAM 62.8 %），0 告警
**触发诉求**：① 心率血氧在正常波动内当正常处理；② 取消 `S`/`~` 标记；③ 检测到数据后一直打印在屏幕上，直到下次检测到数据；④ 心率、血氧、摔倒在异常时"标红"

---

## 一、先说一个绕不过去的硬件约束

这块屏是 **0.96" SSD1306**，**单色**。

| | 事实 |
|---|---|
| 像素 | 128×64，**每像素只有"亮 / 灭"两态** |
| 颜色 | **物理上不存在红色子像素**，不存在 RGB |
| 结论 | **"标红"在这块硬件上无法实现** —— 不是软件限制，是面板没有红色发光体 |

因此第 ④ 条改用该屏能表达的**最强强调手段**：`OLED_ReverseArea()` 的**反色高亮**（该区域白底黑字，与周围黑底白字形成最大反差），视觉上最接近"红底白字"的告警感。**已在交付时向用户明说，未假装实现了红字。**

若确实需要真彩色告警，硬件上只能换屏（如 0.96" SSD1331 彩色 OLED / ST7735 TFT），属改板级工作。

## 二、四条诉求的落地

| # | 诉求 | 落地方式 |
|---|---|---|
| ① | 正常波动内当正常处理 | 高亮阈值取**生理正常带**：心率 **60–100 bpm**、血氧 **≥95 %**。带内一律正常显示，不因抖动触发 |
| ② | 取消 `S`/`~` 标记 | 删掉 `OLED_ShowChar(79,16, app_hr_stable ? 'S' : '~', …)`，屏上不再有该字符 |
| ③ | 检测到就保持打印 | **hold-last**，见第三节 |
| ④ | 异常标红 | **反色高亮**，阈值可 SWD 在线改写，见第四节 |

## 三、保持显示（hold-last）的实现与边界

### 3.1 改的是什么

v2.6 的策略是"门控一失败就切 `---`"。v2.7 反过来：

```c
/* --- no contact / unusable signal: HOLD the last valid reading --- */
/* Once a reading has been validated it stays on screen until a later
   window produces a fresh one - it is never blanked back to "---". */
if (!app_ppg_ok) {
    if (app_ppg_bad >= (uint32_t)APP_LOSS_WINDOWS) {
        app_hr_n = 0; app_spo2_n = 0;         /* 只清滑动窗 */
        app_hr_wr = 0; app_spo2_wr = 0;
        app_hr_rej_run = 0;
    }
    app_ppg_record();
    return;                                    /* 不清 app_hr_ok / app_hr_disp */
}
```

**关键点**：失联时**只重置滑动窗**，**不动** `app_hr_ok` / `app_spo2_ok` / `app_hr_disp` / `app_spo2_disp`。

### 3.2 为什么必须先清滑动窗

滑动窗保留着手指还在时的样本。如果只做 hold 而不清窗，手指重新按上时新样本会和**几分钟前的旧样本**混在一起求平均，收敛结果无意义（相当于拿两次测量的数据算一个人）。所以：**显示值保持，但数据池清空** —— 这两件事必须分开。

### 3.3 数字与高亮不会不同步

高亮判据写成：

```c
if (app_hr_ok && (app_hr_disp < app_hr_warn_lo || app_hr_disp > app_hr_warn_hi))
    OLED_ReverseArea(47, 16, 24, 16);
```

它依赖 `app_hr_ok` —— 而 `app_hr_ok` 在 hold-last 下**不会转 0**，所以数字留着、高亮也留着，**不会出现"数字还在但底色变了"**。这是刻意设计的耦合：高亮跟的是**屏幕上正在显示的那个值**，不是"这一瞬间有没有新信号"。

## 四、异常高亮

| 字段 | 反色区域 | 触发条件 | 默认阈值 |
|---|---|---|---|
| 心率 | `OLED_ReverseArea(47,16,24,16)` | `< 60` 或 `> 100` bpm | `app_hr_warn_lo=60` / `app_hr_warn_hi=100` |
| 血氧 | `OLED_ReverseArea(47,32,24,16)` | `< 95` % | `app_spo2_warn_lo=95` |
| 跌倒 | `OLED_ReverseArea(80,48,16,16)` | `app_fall_show == 1` | —（沿用 `09` 的 3072 LSB 门限） |

三个阈值都是 `volatile` 变量，**可在 RAM 里在线改写，不用重烧**。

### 内存布局（一把 `mww` 同时改三项）

| 地址 | 偏移 | 变量 | 默认值 |
|---|---|---|---|
| `0x20000004` | `[04]` | `app_spo2_warn_lo` | `95` |
| | `[05]` | `app_hr_warn_hi` | `100` |
| | `[06]` | `app_hr_warn_lo` | `60` |
| | `[07]` | 填充 | `0` |

默认打包字 = **`0x003c645f`**。

> ⚠️ 地址随固件重编译会变，取址请现查：
> `arm-none-eabi-nm -S -n build/APP.elf | grep -E "app_hr_warn|app_spo2_warn"`
> （跌倒是另一组：`grep app_fall_`）

## 五、顺带修掉的一个老 bug：按位或残影

`OLED_ShowChar()` / `OLED_ShowChinese()` 是**按位或**写入显存的（不熄旧像素）。于是：

| 场景 | 现象 |
|---|---|
| 心率 `119` → `89` | 显示成 `889`（前一位的 1 没被擦掉，只剩 8 的部位残影） |
| 跌倒 `是` → `否` | 两个字形叠加成"糊字" |

修复：画之前先清区域。

```c
OLED_ClearArea(47,16,24,16);   /* 心率数字域，3 位宽 */
OLED_ClearArea(47,32,24,16);   /* 血氧数字域 */
OLED_ClearArea(80,48,16,16);   /* 跌倒"是/否"的那一格 */
```

宽 24 覆盖 3 位数字；宽 16 是"是/否"一个中文字的宽度。

## 六、实测证据

工具：`firmware/MAX30102/gcc/tools/ppg_read.py`（SWD 带电读回，自动把 OLED 显存按字模解码成文字）

### 6.1 有手指按住

```
OLED framebuffer, decoded:
  y=0  温度：29℃
  y=16 心率：120  BPM     <INVERSE x=47..71>
  y=32 血氧： 97  %                              <- 无高亮（97 ≥ 95）
  y=48 是否跌倒：否                               <- 无高亮
what the display layer decided:
  HR     ok=1 disp=120    SpO2 ok=1 disp=97
```

- `x=79` **已无 `S`/`~` 字符** → 诉求 ② ✅
- 120 > 100 → 心率行命中反色；血氧 97、跌倒"否"均未误触发 → 诉求 ④ 正确极性 ✅

### 6.2 受控双向测试（在线改阈值，不重烧）

写 `0x20000004 = 0x003c8264` → `spo2_warn_lo=100`、`hr_warn_hi=130`：

| 字段 | 值 | 阈值 | 结果 |
|---|---|---|---|
| 心率 | 122 | ≤ 130 | **高亮消失** ✅ |
| 血氧 | 98 | < 100 | **高亮出现** ✅ |

写回 `0x003c645f` 后复核恢复正常。→ **两条通路都能触发与撤销，且在线调参确实生效** ✅

### 6.3 松手（hold-last 端到端验证）

```
OLED framebuffer, decoded:
  y=0  温度：28℃
  y=16 心率： 89  BPM      <- 无高亮（89 在 60–100 内）
  y=32 血氧： 97  %
signal quality of the last window (gate G1):
  IR DC = 604 LSB   AC p-p = 141 LSB   PI = 233‰
  gate verdict = FAIL   consecutive failures = 10
what the display layer decided:
  HR     ok=1 disp=89  n=0        SpO2 ok=1 disp=97  n=0
  raw DSP output : ch_hr_valid=0 n_heart_rate=-999 | ch_spo2_valid=1 n_sp02=99
```

逐窗 trace（松手前后）：

```
 win |  IR DC | AC p-p |  PI | raw HR | flags | shown
 138 | 138453 |   3469 |  25 |    166 | 1101  | HR=89  SpO2=97   <- 手指还在
 139 | 133169 | 137247 |1030 |   -999 | 0101  | HR=89  SpO2=97   <- 抬手瞬态
 143 |  22930 | 140795 |6140 |   -999 | 0101  | HR=89  SpO2=97
 144 |    625 |   2047 |3275 |     60 | 0101  | HR=89  SpO2=97   <- 已到暗电平
 145 |    591 |    131 | 221 |   -999 | 0101  | HR=89  SpO2=97
 153 |    716 |    116 | 162 |    206 | 0101  | HR=89  SpO2=97   <- 第 15 个窗仍保持
```

**结论**：松手后连续 **15 个窗口**（直流 580–720 LSB，纯暗电平）门控**全部失败**、滑动窗 `n=0`，而屏显**始终保持 `89 / 97 %`**，心率行**无高亮**（89 在正常带内）。→ 诉求 ①③ 与 ④ 的同步性全部 ✅

同时 `app_fall_hits = 0`（`app_fall_polls = 26468`）—— 全程无误报跌倒。

### 6.4 一个必须记下的副作用

trace 第 149–153 窗，**暗电平上 raw DSP 仍报 `n_heart_rate = 200 / 146 / 187 / 206`**，同时 `ch_spo2_valid=1 / n_sp02=99`。

这**再度印证 `10` 的结论**：`algorithm.c` 的血氧通路**没有任何合理性门控**，99 % 本来就落在生理范围内，**纯数值判据永远拦不住**。挡住它的只能是"信号存不存在"——即 G1。心跳读数则是因为门控失败根本没被 ingest，所以 `disp` 仍是 89。

## 七、复现命令

```bash
export PATH="$HOME/tools/xpack-arm-none-eabi-gcc-14.2.1-1.1/bin:$PATH"
cd firmware/MAX30102/gcc

# 生成 + 编译
python app/make_app.py && SHELL=/usr/bin/bash /c/mingw/mingw64/bin/mingw32-make.exe -j4 APP=1

# 烧录
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c "adapter speed 20" \
        -c "init" -c "reset halt" -c "program build/APP.elf verify" -c "reset run" -c "exit"

# 带电读回（自动解码屏显 + 门控 + 逐窗 trace）
python tools/ppg_read.py

# 在线改高亮阈值（示例：血氧门限抬到 100，让 99% 也高亮）
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c "adapter speed 20" -c "init" -c "halt" \
        -c "mww 0x20000004 0x003c8264" -c "resume" -c "exit"
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c "adapter speed 20" -c "init" -c "halt" \
        -c "mww 0x20000004 0x003c645f" -c "resume" -c "exit"   # 恢复默认
```

## 八、遗留

1. **心率估计在弱信号下会漂**：本轮同一颗手指上，屏显从 `119` 一路收敛到 `89`（raw 在 80–214 间跳，累计剔除 31 个离群值）。8 窗滑动 + 中位裁剪能剔掉尖峰，但**底层灌注指数只有 3–18‰**（下限 3‰），估计值仍带较大不确定度。**用户按实一点重测**是唯一解法，代码侧不宜再压。
2. **"标红"是替代方案**：反色高亮 ≠ 红色。若验收必须红色，需换彩色屏（改板）。
3. **血氧无时序回归**：本轮与心率同步验证，未单独做长时间稳定性测试。
4. 显示值为 **hold-last**，因此**屏上数字不代表"此刻"**。若后续要区分"实时 / 陈旧"，需要引入时间戳或降级显示（如陈旧值加下划线）。当前按用户要求「一直打印」实现，未加时效标记。

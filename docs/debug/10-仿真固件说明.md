# 10 · 仿真专用固件说明

> 这份固件**只用于 Proteus 仿真**，不是实物固件。
> 实物请继续用 `firmware/MAX30102/USER/main.c`（一行未改）。

## 1. 为什么需要一份单独的仿真固件

`sim/proteus/SIT_sim.pdsprj` 里的器件与实物并不等价：

| 项 | 实物 | 仿真工程 | 后果 |
|---|---|---|---|
| MAX30102（心率/血氧） | 有 | **没有这个器件** | 原固件会卡在 `while(MAX30102_INT==1)`，永远进不了主循环 |
| MPU6050（跌倒） | 有 | 没有 | 跌倒判定没有数据源 |
| DS18B20（温度） | 有，实测正常 | 有符号，但加载的是 `DS1822.MDF` 模型 | 单总线命令写不进去，读回恒为 `0xFFFF` |
| STM32 主频模型 | 72 MHz | `CLOCK_SCALE = 8 Times`（≈64 MHz） | 所有延时偏慢约 12.5%，周期类测量全部偏移 |

DS18B20 一项做过 **48 组时序组合**的自动扫描（开漏/推挽 × 6 组时隙 × 2 种输入模式 ×
2 种命令重发），全部读不出合法暂存器（配置寄存器应为 `0x1F/0x3F/0x5F/0x7F`），
判定该模型无法与当前 MCU 模型通信。

## 2. 这一版的行为

| 功能 | 数据来源 | 说明 |
|---|---|---|
| 温度 | **RV2 电位器（首选）** | 抽头 → PA0(ADC1_IN0)，0~3.3 V 线性映射为 **15.0~45.0 ℃**，显示一位小数 |
| 温度（兜底） | 固件模拟 | ADC 读不到（电位器悬空/超时）时：25 ℃ 起每秒 1 ℃ 升到 38 ℃ 再降回 |
| 心率 | 固件模拟 | 66→90→66 BPM 三角波，每秒 1 格，约 24 s 一个来回 |
| 血氧 | 固定占位 | 97 |
| 跌倒 | **真实逻辑** | SW3（PB1 低电平有效，20 ms 去抖）→ `FALL:YES` |
| 蜂鸣器 | **真实逻辑** | 跌倒时 PA12 拉低（有源蜂鸣器，低电平响） |

屏幕第 2 行右侧是**数据来源标记**：

| 标记 | 含义 |
|---|---|
| `POT` | 温度来自 RV2 电位器（**正常应显示这个**） |
| `SIM` | ADC 读不到，退回软件模拟温度 |
| `DS18` | 真的从 DS18B20 读到（当前仿真里不会出现） |

答辩口径：**仿真工程缺少 MAX30102、DS18B20 也没有可用模型，所以温度由电位器模拟、
心率由固件生成；跌倒判定、报警、OLED 显示、按键逻辑全部是真实代码路径。实物上
温度/心率由传感器采集，已实测正常。**

## 3. 接线（与 `SIT_sim.pdsprj` 一致）

| 外设 | 引脚 |
|---|---|
| OLED（软件 I2C） | SCL→PA5，SDA→PA6 |
| **RV2 电位器抽头** | **PA0（ADC1_IN0）**，两端接 3.3 V / GND |
| DS18B20 DQ | PA8（4.7 kΩ 上拉到 3.3 V） |
| 蜂鸣器（有源，低电平响） | PA12 |
| 心跳脉冲输入 | PB0（上拉输入，接 CLOCK 源） |
| 跌倒开关 SW3 | PB1（上拉输入，另一端 GND） |

**Proteus 里怎么改变电位器**：运行中点一下 RV2 后按 **↑/↓**（1% 一步，约 0.3 ℃）；
停止仿真时双击 RV2 改 `STATE`（0~100）。

## 4. 想换成真传感器怎么办

1. **换 DS18B20 模型**：在 Proteus 里换成自带的 `DS18B20` 数字温度计模型（或 `DS1621`）。
   固件不用改——上电会自动扫描时序，读通后标记自动从 `POT/SIM` 切成 `DS18`。
2. **心率想跟 CLOCK 联动**：把 `USER/main.c` 里的 `HR_USE_PULSE` 改成 `1`，心率改用
   PB0 的 EXTI 外部中断测周期。注意 `Timestep per Frame` 太粗（默认 50 ms）时读数会偏。
3. **想让"温度 > 32 ℃ 报警"可演示**：把实物固件里那条 `else if (Temp > 32) Buzzer_on();`
   加回仿真版即可（当前为演示稳定性未启用，否则模拟温度爬到 38 ℃ 会一直响）。

## 5. 编译与部署

```bash
# 编译（Keil 命令行）
"C:/Keil_v5/UV4/UV4.exe" -b "…/firmware/MAX30102_sim/USER/IIC.uvprojx" -j0 -o build.log

# 部署（Proteus 固定加载这个路径）
cp firmware/MAX30102_sim/OBJ/IIC.hex sim/proteus/IIC.hex
```

- 产物：`firmware/MAX30102_sim/OBJ/IIC.hex`
- 编译结果：`0 Error(s), 0 Warning(s)`，Code ≈ 5.5 KB（ROM 充裕）
- 修改属性后 Proteus 需**停止再运行**才会加载新固件

## 6. 仿真环境里的两个已知限制

1. **蜂鸣器要靠模型**：BUZ1 若被勾了 `Exclude from Simulation`，IO 怎么拉都不会响；
   且 `Operating Voltage` 默认 12 V，3.3 V 电源轨下要改成 **3.3**。
2. **主频偏差**：MCU 模型 `CLOCK_SCALE=8`，与固件假设的 72 MHz 差 12.5%，
   所以任何"用时间算出来的量"（心率、周期）都会偏；这也是心率改用心率节律的原因。
   把 `Clock Scale` 改成 `9 Times` 可消除该项偏差。

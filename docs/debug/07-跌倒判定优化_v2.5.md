# STM32 健康监测仪 · 跌倒判定优化报告 v2.5

日期：2026-10-16 20:55
固件：`firmware/MAX30102/gcc/app/app_main.c`（由 `app/make_app.py` 生成）、`make APP=1`
实测环境：板子平放桌面，无人触碰（被动值守）

---

## 一、结论（先行）

1. **判定频率 0.52 Hz → 87.7 Hz（×166）**。原判定一圈只跑一次，一圈 1.9 s；真跌倒冲击只有几十 ms，
   大概率整段落在两次判定之间 —— 这就是"灵敏度不如以前"的根因，不是阈值问题。
2. **判据从"单轴 2 秒差值"换成"合矢量 |a| 去重力偏差"**。前者对"单纯翻转板子"极其敏感
   （2 秒内翻 15° 就够触发），后者对倾斜完全免疫。
3. **阈值由数据定标**：单轴 500 LSB → **|a| 偏差 3072 LSB（≈2.5g）**。
4. **新增两道加固**：连续 2 拍超阈才报警（≈23 ms）；全零样本（传感器掉电/线被碰掉）直接丢弃。
5. 实测（120 s + 40 s 被动值守）：`hits=0`、`glitch=0`、`zero=0`、`mpu_err=0`，
   静止时最大 |a| 偏差仅 **119 LSB（0.058g）**，对阈值有 **≈26 倍余量**。

## 二、定标所用的数据（全部本机实测）

| # | 场景 | 判定次数 | 每步幅值分布 | 结论 |
|---|---|---|---|---|
| A | 板子静止未被触碰，90 s | 7859 | <500 LSB 7844 ／ 500–1k 10 ／ 1k–2k 4 ／ **≥2k 0** | 单轴单步上限 < 2000 LSB |
| B | 手轻触（抖动线材/轻拍），180 s | 15684 | <500 15599 ／ 500–1k 54 ／ 1k–2k 27 ／ **2k–4k 3** ／ ≥4k 0 | 轻触最坏单轴单步落在 2–4 kLSB 档，180 s 内仅 3 次 |
| C | v2.5 被动值守，120 s | 10406 | |a| 全程 1929–1966 LSB（0.942–0.960g）；最大偏差 **119 LSB** | 静止噪声极小 |

> 传感器量程 ±16g → **2048 LSB = 1g**。
> 真跌倒冲击（文献典型 3–6g）= **4096–6144 LSB 的 |a| 偏差**。

**定阈推导**：轻触最坏单轴单步 < 4000 LSB（≈1.95g），对应 |a| 偏差约 2g；真跌倒 ≥3g。
取 **3072 LSB（2.5g）** 夹在中间，向下留 ~0.5g 抗误报余量，向上仍能覆盖 3–6g 的真冲击。

## 三、改动清单与依据

| # | 改动 | 依据 |
|---|---|---|
| 1 | 判定挂进两段**纯等待**（MAX30102 等 INT + DS18B20 转换等待），频率 0.52 Hz → **87.7 Hz** | 真冲击只有几十 ms，0.52 Hz 必然漏掉 |
| 2 | 判据：单轴 2 s 差值 → **合矢量 \|a\| 去重力偏差** | 单轴差值的时间基准是整圈（1.9 s），翻 15° 就报跌倒 |
| 3 | 阈值 500 → **3072 LSB（\|a\| ≥ 2.5g）** | 见第二节推导 |
| 4 | **连续 2 拍超阈**才置报警位；单拍尖峰只计 `app_glitch_cnt` | 轻触产生的超阈样本是孤立尖峰，真冲击在 87.7 Hz 下必连续 ≥5 拍 |
| 5 | **全零样本直接丢弃**（`ax==ay==az==0`） | 见下方"关键修复" |
| 6 | 删掉主循环里一次阻塞式 `MPU6050_GetData`（50 kHz 下 12 次单字节读 ≈9.4 ms）+ 死分支 `else if (Temp > 32)` | 白耗 9.4 ms，且 `WaitEvent` 超时后静默返回脏数据，是多余的毛刺源 |

### 关键修复：`app_mpu_zero`

上一轮"轻触实测"后半段 `hits` 从 0 飙到 8584，`mag_min` 恒 0 —— 那是**电源被碰掉**：
MPU 三轴全返回 `0x00` → `|a| = 0` → `dev = |0-2048| = 2048` **恰好压在旧阈值上** → 每拍都报警。
按旧代码，一条被碰掉的线就能把报警永久锁死。v2.5 对全零突发直接丢弃并计入 `app_mpu_zero`，
不参与任何判定。

| 40 s（重烧校验后） | 3507 | ✔ | — | — | **0** | 0 | 0 | 0 | 0 |

- 生效率：120 s 内 10406 次判定全部落在 |a| < 1.5g 档，第 2~6 档全为 0。
- `app_fifo_level = 0` → 87.7 Hz 的判定没有拖慢 MAX30102 采样、无丢样。
- 业务链路：`app_ds_ok=1`、`Temp=25℃`、`app_cycle` 正常推进（~2.0 s/圈）。
- OLED：显存 433/1024 非零、8 页全覆盖，四行界面完整（温度／心率／血氧／是否跌倒：否）。
- 芯片内镜像与本次构建 `verify_image` 校验一致（11960 B 全部匹配），无需重烧。

> **一处必须说明的保留项**：本轮验证时传感器上**没有手指**，所以读到的 `n_heart_rate`（272/400 BPM）、
> `n_sp02`（-999 哨兵值）是无效值，OLED 上显示为 `00`。MAX30102 链路本次未改动、FIFO 无积压，
> 但要坐实"业务不回归"，需要手指置于传感器上复测一次（v2.4 已实测过 82/70/96 BPM、97–98% SpO₂）。

## 五、在线可调项（SWD 直接改，不用重烧）

| 符号 | 地址 | 默认 | 含义 |
|---|---|---|---|
| `app_fall_thresh` | `0x20000006` | 3072 | 冲击门限，|a| 相对 1g 的偏差（LSB） |
| `app_fall_need` | `0x20000004` | 2 | 需连续超阈的拍数 |

```bash
# 更灵敏：门限降回 2g
openocd ... -c "mww 0x20000006 2048"
# 更保守：要求冲击持续 3 拍
openocd ... -c "mww 0x20000004 3"
```

其余诊断量（`app_fall_polls` `0x20001010`、`app_fall_hits` `0x2000100c`、`app_glitch_cnt` `0x20000ffc`、
`app_mpu_zero` `0x20001000`、`app_mpu_err` `0x20001004`、`app_dev_max` `0x20000008`、
`app_dbin` `0x20000fdc` 六档直方图）均可直接 `mdw` 读。

## 二、黑屏：根因与修复（已闭环）

### 根因

`periodic_scan()` 里的 `pin_survey_port(GPIOA, "PA", 0xE600, ...)` **不跳过 PA5 / PA6**，
把 OLED 的两根线重配成输入模式；而 `oled_show()` **只改 ODR、不重写 CRL**，
于是从第一次扫描之后就永久空写 —— 屏是亮的，但内容永远是 `OLED_Init()` 留下的全清画面。

**证据（修复前）**：`GPIOA_CRL = 0x88888888`，PA5/PA6 nibble = `0x8`（输入下拉，锁死）。
**对照**：MPU6050 的 PB10/PB11 在 `bb_scan` 后每一步都重新 `GPIO_Init`，所以不受影响。

### 修复

在 `diag_live.c` 新增 `oled_pins_fix()`，`oled_show()` 第一行调用，每帧把 PA5/PA6
恢复成开漏输出并释放为高：

```c
static void oled_pins_fix(void)
{
    GPIO_InitTypeDef g;
    g.GPIO_Pin   = GPIO_Pin_5 | GPIO_Pin_6;
    g.GPIO_Speed = GPIO_Speed_50MHz;
    g.GPIO_Mode  = GPIO_Mode_Out_OD;
    GPIO_Init(GPIOA, &g);
    GPIO_SetBits(GPIOA, GPIO_Pin_5 | GPIO_Pin_6);
}
```

### 验证（本轮实测）

| 项目 | 修复前 | 修复后 |
|---|---|---|
| `GPIOA_CRL` | `0x88888888`（PA5/PA6 = 输入下拉） | **`0x87788888`**（PA5/PA6 = 开漏输出 50 MHz） |
| OLED 显存非零字节 | 0 / 1024 | **480 / 1024** |
| 分页分布（8 页） | 全 0 | **60 / 68 / 39 / 75 / 55 / 62 / 58 / 63** |

> 注：同一时刻 `GPIOB_CRL = 0x88888888`（PB7 处于输入态）属正常 —— 那是 `periodic_scan()`
> 的收敛状态，OLED 只依赖 PA5/PA6，不受影响。

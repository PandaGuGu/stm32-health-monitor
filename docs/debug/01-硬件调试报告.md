## 一、结论（先行）

**固件烧录成功并运行，但卡死在初始化阶段——`ds18b20_init()` 里的死等循环，程序永远进不了主循环。**

这是**硬件侧问题**（DS18B20 未应答），不是固件构建问题。GCC 构建的固件本身完全正常。

## 三、调试发现（GDB 调用栈）

附加 GDB 后暂停，调用栈如下：

```
#0  0x08000760  ds18b20_rst ()   ds18b20.c:68
#1  0x0800089a  ds18b20_init ()  ds18b20.c:234
#2  0x0800016c  main ()          main.c:88
```

多次采样 PC（8 次中 6 次）都落在 `0x08000756 ~ 0x08000760`，即 `ds18b20_rst()` 的**第一个等待循环**里，证明是**死循环**而非偶发。

---

## 四、根因分析

`HARDWARE/DS18B20/ds18b20.c` 第 61~70 行：

```c
void ds18b20_rst(void)
{
  mode_output();                              // PA8 输出
  GPIO_ResetBits(GPIOA, GPIO_Pin_8);          // 拉低 DQ
  delay_us(600);                              // 复位脉冲 600us
  GPIO_SetBits(GPIOA, GPIO_Pin_8);            // 释放
  mode_input();                               // PA8 输入上拉
  while(GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_8));   // ← 第68行：无超时死等
  while(!GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_8));
}
```

**第 68 行是无限循环，没有超时保护。** DS18B20 正常时应答时会拉低 DQ 60~240us，循环随即退出；若器件不存在/未接/接线错误，DQ 被内部上拉保持高电平，循环**永久卡死**。

实测旁证：
- 暂停时读 `GPIOA_IDR = 0x0000DFFF` → **PA8 = 1（始终高）**，从未出现过器件应答的低脉冲。
- `ds18b20_init()` 在第 234 行调用 `ds18b20_rst()`；main 在第 88 行调用 `ds18b20_init()`。

**因此 DS18B20 在 PA8 上没有应答。**

---

## 五、连锁影响

因为卡在 main 第 88 行（初始化早期），后续代码**全部未执行**：

| 行 | 未执行的初始化 | 现象 |
|---|---|---|
| 84 | `max30102_init()` | 心率/血氧始终 0 |
| 86 | `MPU6050_Init()` | 姿态数据 AX~GZ 始终 0 |
| 93 | `MPU6050_GetData()` | 同上 |
| 102~117 | 首次 500 点采样 + 算法 | `n_heart_rate`/`n_sp02` 始终 0 |
| 119~ | 主循环 | OLED 永远停在初始静态画面 |

所以「所有变量都是 0」不是算法 bug，而是**根本没跑到**。

---

## 六、DS18B20 接线核对（据 main.c 注释）

| 信号 | 引脚 |
|---|---|
| DQ | **PA8** |
| VCC | 3.3V（**勿接 5V**） |
| GND | GND |
| 上拉 | DQ 与 3.3V 之间建议接 **4.7kΩ** 外部上拉 |

代码仅依赖 STM32 内部上拉（IPU，约 40kΩ），长线或劣质模块可能不足，建议补外部 4.7kΩ。
